### 제작과 선택

E의 원래 셀에서 고정 영역 `(64,128)-(128,192)`을 정사각형으로 확대했다. 세 생성 원본은 모두 실제 1254×1254이며 편집 없이 보존했다. 전체 정사각형을 같은 배율로 256×256으로 축소해 4배 E 셀의 고정 위치 `(256,512)`에 합성했다. 개별 발 이동·비틀기·반전, 가이드 기반 윤곽 자르기, 좌표·몸체·가림 마스크 변경은 하지 않았다. 원래 가림 마스크와 몸체를 합성해 생성된 상체·치마·칼은 사용하지 않았다.

첫 두 후보도 밴드가 위에 남아, 세 번째는 기존 후보 대신 고정 가이드 한 장을 직접 기준으로 그렸다. Windows 참조 경로 인자가 생성 전에 거부되어, 직접 확인한 같은 참조 이미지를 대화 이미지로 전달했다. 성공한 생성은 E만 3회다. 재생성으로 정확한 정렬을 달성하지 못했으며 실패 후보도 남겼다.

### 원화의 독립 관찰과 가이드 비교

발목띠는 **생성 원본의 RGB만** 사용해 쪽빛 연결 성분을 검출하고 외접 상자 중심을 육안 확인했다. 검출 함수는 가이드 좌표를 읽지 않는다. 뒤꿈치·발끝은 흰 버선의 보이는 뒤쪽/앞쪽 중심선을 육안 추정했다. 밑창 외곽 끝과 해부학적 중심을 혼동하지 않도록 정의와 불확실도를 `observations.json`에 남겼다. 스타일화된 그림의 실제 해부학적 관절을 확정한 검사가 아니며, 가려진 먼 발끝은 좌표를 추정하거나 가이드에서 복사하지 않았다.

### 미술 검토와 남은 문제

- 먼 발의 흰 버선·밑창 노출은 유지했다. 다만 보이는 뒤쪽 흰 부분이 발끝처럼 읽힐 수 있어 뒤꿈치 구성은 추가 검토가 필요하다.
- 가까운 발의 두 가로 짚끈과 흰 버선 사이 간격은 확인했다. 뒤꿈치 고리를 세 번째 가로 끈으로 세지 않았다. 먼 발은 한 줄과 짧은 조각이 보이지만 나머지가 가까운 다리에 가려져 **분리된 두 가로 끈의 완전한 검수는 미완료**다.
- 발목띠는 여전히 높고 위치가 어긋난다. 신발 길이·밑창 높이도 미해결이다. 그림을 사후 이동·왜곡해 수치만 맞추지 않았다. 생성 원화의 화풍과 기존 저해상도 상체 사이 차이, 가림 경계의 기존 조각도 승인 전 미술 검토 대상이다.

### 파일·재현·보존

`idle-e-revision-1/`의 `source-attempt1/2/3.png`·각 `prompt-attempt*.txt`가 생성 기록이다. `guide-input.png`, `before-input.png`, `layout.json`은 고정 참조 배치다. `attempt*-master-e.png`, `master-e.png`, `visible-legs-e.png`는 **E만의 검토 PNG**이고 게임이 읽지 않는다. `before-e.png`, `comparison.png`, `attempts-comparison.png`, `alignment.png`(가이드 십자), `observed-landmarks.png`(독립 관찰 원)는 비교 자료다. `observations.json`, `validation.json`, `regression-check.json`이 관찰·측정·회귀 기록이다.

`python scripts/prepare_leg_idle_e_review.py`(Pillow/NumPy)로 재현한다. 외부에 연결된 밝은 배경만 추출했고 가이드로 신발 윤곽을 자르거나 소형 조각을 골라 제거하지 않았다. 불투명 보호 픽셀 변경 **세 후보 모두 0**, E 셀 여백 통과다. 반투명 가림 경계에는 새 다리 배경색이 섞일 수 있어 완전 RGBA 동일성을 주장하지 않는다. **비교·검사 출력 14개**는 두 번 실행해 SHA-256이 모두 일치했고 `git diff --check`도 통과했다. 기존 미술 파일 22개는 Git 기준과 바이트 동일, 그 외 기존 텍스트 6개는 작업 사본의 CRLF/LF 차이만 있었고 검사 전후 원시 SHA-256은 같았다. 최초 직접 바이트 검사가 `crop-layout.json`의 줄바꿈 차이로 중단돼, PNG/참조는 바이트 비교를 유지하고 기존 텍스트만 CRLF→LF 동등성과 검사 전후 원시 해시를 함께 확인하는 방식으로 복구했다. 새 출력 JSON은 LF로 고정했다. 상세는 `regression-check.json`에 기록했다. 기존 `src/`·`assets/`·가이드/좌표·몸체/가림·기존 생성 원본·기존 검수 기록·다른 방향을 보존했고 `sources/`에는 쓰지 않았다.

게임 미연결이므로 이번에 C/SDL 빌드·게임 실행·실기기 검사는 수행하지 않았다. 확정 설정이 없어 GAME_BIBLE은 변경하지 않았다. 복구 시 새 폴더와 새 준비 스크립트만 제외하고 이전 E 후보를 그대로 사용하면 된다. **현재 정지 검수는 미통과다. 사용자에게 이 결과를 보고하고 확인을 기다리며 다음 방향으로 넘어가지 않는다. 걷기·게임 연결·병합·배포 금지 상태를 유지한다.**

## 검사 결과

원본 몸체의 가림 마스크 안 **불투명 보호 픽셀 변경은 0**이다. 반투명 경계는 원본 레이어를 그대로 유지하지만 새 다리와 합성되므로 최종 RGBA 동일성 검사 대상에서 제외했다. 셀 가장자리 2px(192px 환산) 여백은 8방향 모두 통과했다.

아래 IoU는 보이는 가이드 색 영역과 추출한 다리 알파의 비교다. 치마 속 전체 다리 IoU와 같지 않다. 최하단 y는 192px 셀로 환산한 보이는 다리 전체의 alpha≥128 경계다. 접지 범위 175~177은 방향별 외곽 하단에만 적용한 예비 검사이며 두 발 각각의 접지 검사와 같지 않다. **관절 위치를 JSON으로 그대로 복사해서 오차 0으로 기재하지 않았다.** 독립적으로 판독한 관절 랜드마크가 없어 최대 관절 오차와 발별 접지 실패 수는 미측정이다.

## 남은 문제와 복구/후속 작업

1. 생성 시 발목·신발 위치와 부피가 가이드에서 벗어났다. 그림을 이동·비틀거나 가이드를 바꿔 수치를 맞추지 않았다. 정지 포즈별로 가이드에서 다시 그려 좌표를 맞춰야 한다.
2. E의 먼 발이 충분히 드러나지 않고, 일부 짚신 끈이 요구한 독립된 두 줄보다 Y자 형태에 가깝다. 버선코·뒤꿈치 고리도 방향별 추가 검토가 필요하다.
3. 추출 경계에 밝은 테두리, 제공된 가림 마스크 경계 근처에 이전 원화 조각이 남을 수 있다. 가림 마스크/상체 원본을 임의로 바꾸지 않고 후보를 보류했다.
4. 제공 JSON은 정지 두 발을 모두 contact=true로 표시하지만 원근에 따른 발의 화면 y가 다르다. 먼 발의 개별 접지 검사는 Claude의 투영 정의 확인이 필요하다. 이번 결과의 오차를 그 문제로 정당화하지 않는다.
5. 걷기 64프레임·실행용 PNG·90ms GIF·게임 렌더·보행 깜빡임은 미제작/미검증이다. 디자인과 정지 정렬 검수가 통과하기 전 걷기로 넘어가지 않는다.

실패 후보의 원본과 전체 프롬프트를 보존했으므로 같은 정지 가이드에서 다시 제작할 수 있다. 상체·게임 파일을 되돌리는 복구는 필요하지 않다.

## 재현과 회귀 확인

`python scripts/prepare_leg_gear_design_review.py` (Pillow, NumPy 필요). 제공 입력 해시는 `preparation.json`에 있다. 이 스크립트는 후보 PNG 합성/검토 측정만 하며 게임 에셋에 설치하지 않는다.

재현 스크립트를 다시 실행해 생성 PNG 5장과 preparation.json 총 6개 파일의 SHA-256이 재실행 전후 모두 같은 것을 확인했다.

사용자에게 디자인과 미통과 항목을 함께 보여주는 Draft PR로 보관한다. 승인본·병합 가능 상태가 아니며, 병합·배포·걷기 착수 승인 요청은 하지 않는다.

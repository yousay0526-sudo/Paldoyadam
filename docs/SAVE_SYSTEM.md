## 플레이 흐름과 저장 시점

- 유효한 기본 저장 또는 복구 가능한 백업이 있을 때 타이틀에 **이어하기**가 표시된다. Space/Enter도 이어하기를 우선한다.
- **새 여정**과 **바로 마을로** 모두 기존 저장이 있으면 덮어쓰기 확인/취소를 거친다. Escape는 확인을 취소한다. 서장 중 건너뛰기는 같은 여정을 계속한다.
- 새 여정은 즉시 저장한다. 이후 실제 시뮬레이션 값의 변경을 **최대 1초 간격**으로 모아 저장한다. 맵 이동, 조사·처치·회수, 전달·보상, 거래·장착·무공 배치·증강 선택이 완료된 상태를 기록한다. 이동/피해/소모품 사용도 같은 간격으로 함께 기록한다. 변경이 없으면 쓰지 않는다.
- 대화 중에도 저장 간격은 진행한다. 화면 보간을 원래 좌표로 되돌린 뒤 저장하므로 렌더링용 임시 좌표를 기록하지 않는다.
- 타이틀 복귀·수련 진입 전·포커스 상실·백그라운드·정상 종료에는 추가 저장을 시도한다. 웹 `pagehide`/숨김 이벤트도 보조한다. 강제 종료로 마지막 미저장 변경 약 1초가 손실될 수 있다. 저장소 자체가 실패하면 이 한도를 보장할 수 없으며 실패 표시와 재시도가 계속된다.
- 성공은 짧게, 실패는 복구될 때까지 표시한다. 공간 부족/저장소 사용 불가/일반 쓰기 실패/손상/미지원 버전을 구분한다. 성공한 기록과 같은 상태도 앞선 저장이 실패했으면 재시도한다.

입력 예약, 공격/무공 중간 프레임, 적 AI의 추격/공격 중간 상태, 길찾기 캐시,
카메라·흔들림·이펙트, UI 대사 인덱스, 포인터·메모리 주소는 저장하지 않는다.
재접속 동안 쿨타임이 실제 시간에 따라 줄어들지는 않는다.

퀘스트 불변식(검증 실패 시 전체 기록 거부): 처치 ↔ 대응 드롭 존재, 회수 수 ↔ 약재 수,
전달 후 약재 0/모두 회수, 단계 ↔ 전달·백정 보상·증강 여부, 소유하지 않은 장비의 장착 금지,
무공 배치의 범위·중복 금지. 비정상 체력·재화·소모품·시간 값과 비유한 수치를 검사한다.
좌표만 복귀 정책에 따라 보정하며, 손상된 퀘스트를 임의로 보상/재화로 메우지 않는다.
검증·보정은 임시 Game에서 끝낸 후에만 실제 게임에 적용한다. 검사 중 선택한 지형도 복구한다.

## PC와 웹 저장소

PC는 `SDL_GetPrefPath("Paldoyadam", "Paldoyadam")` 아래를 사용한다.
`journey-autosave.sav`가 본 슬롯이고 `.bak`은 이전 정상 기록의 복구용 백업이다.
사용자에게 여러 슬롯을 제공하는 기능은 아니다.

1. 명시적 저장 데이터를 `.tmp`에 전부 기록하고 flush·디스크 동기화·닫기를 확인한다.
2. 현재 기본 기록이 유효하면 `.bak.tmp`에 같은 방법으로 보관한 뒤 `.bak`으로 교체한다.
3. 완성된 `.tmp`를 기본 파일로 교체한다. Windows는 UTF-8 경로를 UTF-16으로 변환해 `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)`, POSIX는 같은 디렉터리의 `rename`을 사용한다.
4. 도중 실패하면 기본 정상 파일을 제거하지 않는다. 시작 시 기본 파일이 없거나 유효하지 않으면 검증된 백업을 사용하고 복구 사실을 표시한다. 미완료 tmp는 불러오지 않는다.

웹은 동기식 localStorage를 사용한다. 키는 `paldoyadam.journey.autosave`와
`paldoyadam.journey.autosave.backup`이다. 전체 기록을 16진 문자열 하나로 바꿔 `setItem`으로 교체한다.
백업 또는 기본 키 쓰기가 실패하면 실패를 반환한다. 기본 교체가 실패해도 이전 기본 키는 남는다.
`QuotaExceededError`는 공간 부족, 접근 차단 등의 오류는 저장소 사용 불가로 알린다.
같은 브라우저 프로필·origin(프로토콜/호스트/포트)에서 재접속해야 같은 저장을 읽는다.
다른 주소/프로필/사생활 보호 세션, 사이트 데이터 삭제는 저장 유지 대상이 아니다.
`file://` 단일 HTML의 origin 저장 동작은 브라우저에 따라 다르므로 HTTP(S) 주소 사용을 기준으로 한다.

키 설정은 이 모듈에서 읽거나 쓰지 않는다. #49의 네이티브 `keys.txt` 및 웹 키 설정과 별도의
`journey` 이름을 사용한다. #49를 나중에 병합할 때 main.c 연결부 충돌을 양쪽 보존하며 해소해야 한다.

## 저장 형식 v1

C 구조체 메모리를 덤프하지 않는다. 216바이트의 고정 필드 순서이며 모든 정수는 uint32
little-endian, 실수는 IEEE-754 binary32 비트를 명시적으로 같은 순서로 기록한다.

| 바이트 오프셋 | 필드 |
|---|---|
| 0 / 4 / 8 | `PDY1` 매직 / 형식 버전 1 / 전체 길이 216 |
| 12..23 | 지역, 퀘스트, 재개 모드(일반/증강/완료/사망/서장) |
| 24..47 | 주인공 x/y, 현재/최대 체력, 출혈 잔여/다음 틱 |
| 48..103 | 재화·소모품·약재, 흔적·전달·보상, 장착·소유, 증강·재대결 |
| 104..147 | 쿨타임 3개·무공별 4개, 스와이프 배치 4개 |
| 148..211 | 백정 체력, 멧돼지 3개의 체력·드롭 존재·회수·x/y |
| 212..215 | 앞의 212바이트에 대한 FNV-1a 32비트 체크섬 |

체크섬은 우발적 손상 감지용이며 치팅 방지/인증 수단이 아니다. 범위·단계 불변식을 별도로 검사한다.
향후 필드/아이템/퀘스트를 확장하면 형식 버전을 올리고, 구버전에서 임시 모델로 이행하는
명시적 마이그레이션과 회귀 fixture를 추가한다. 알 수 없는 버전을 현재 구조체로 해석하지 않는다.
다중 슬롯·클라우드·계정·정혼주·수련 트리는 이번 범위에 없다.

## 검증

- `autosave_progress`: 세 지역 왕복 직렬화, 의뢰 전체의 각 처치/미회수/회수/전달/보상 경계,
  일반 대화·서장·증강·완료·재대결·사망 복구, 좌표 보정, 길이 잘림·바이트 변조·미지원 버전·값/단계 불일치,
  기본 파일 손상 시 백업, 임시 파일 쓰기 실패 시 기본 보존, 수련 거부.
- `native_save_session_write` → `native_save_session_restart`: 실제 SDL App 코드의 서로 다른 실행 프로세스에서
  타이틀·이어하기·새 여정 확인/취소·백그라운드·수련·저장 간격·오류 재시도·화면 크기별 버튼 경계를 검사한다.
  전용 fixture 디렉터리를 사용하며 사용자의 실제 여정 파일에 접근하지 않는다.
- `browser_storage_backend` 또는 `node tests/test_save_storage.cjs`: 제품 JS 백엔드의 교체/백업,
  용량 부족·SecurityError·손상·길이 제한·다른 키 보존. 이 검사는 실제 브라우저 재접속 검사가 아니다.

최종 실행 결과와 미검증 범위는 CURRENT_STATE.md 및 PR 검증 기록을 참조한다.
직접 Windows 창 조작과 실제 브라우저 새로고침/재접속은 화면 자동화 중단으로 완료하지 못했다.

실제 디스크 가득 참·정전/프로세스 강제 종료 내구성은 미검증이다. 오류 코드는 재현 가능한 실패 주입으로 검사한다.

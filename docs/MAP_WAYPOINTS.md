# 길목 이정표와 열린 동쪽 출구 · 2026-10-28

마을에서 탐식굴로 나가는 길의 울타리/문짝이 닫힌 것처럼 보여 이동 가능한 길과 그림이 어긋났다. 해당 부분을 열린 흙길로 고치고, 네 왕복 지점의 원형 표식과 떠 있는 이름표를 목제 이정표로 교체했다.

## 구현

- `assets/maps/village.png`: ImageGen 편집 결과 중 동쪽 출구만 부분 적용했다. 바뀐 35,172픽셀의 경계는 (1331,546)..(1535,718)이며, 허용 사각형 x1330..1535/y545..719 밖의 변경은 0픽셀이다. 원본과 생성 결과는 [원화 기록](../art/maps/waypoints-20261028/README.md), 출처/해시는 [provenance.json](../art/maps/provenance.json).
- `assets/maps/waypost.png`, `src/draw.c/h`: 나무 간판·새끼줄·등롱·밑돌을 한 RGBA 소품으로 로드하고, 목적지 이름을 간판 면에 붓글씨로 적는다. 길 가장자리에 두고 주인공/NPC/적과 발 위치 순서로 그린다. 기존 이동용 원은 제거했다. 새 텍스처는 로딩 실패 검사와 해제 경로를 포함한다.
- `src/maps.c`, `art/maps/layout.json`: 이정표 밑돌 네 곳에만 작은 충돌 영역을 추가했다. 출입 판정 중심·거리·도착 좌표와 왕복/전투/의뢰 규칙은 그대로다. 기존 상호작용 버튼 또는 Space를 사용한다.
- `src/main.c`: `--scene exit0`..`exit3` 검토 장면을 추가했다. 순서는 마을→솔바람재, 마을→탐식굴, 솔바람재→마을, 탐식굴→마을이다.

## 검증

Windows / Zig 0.14.1 / SDL 2.32.10 전체 빌드 성공. `ctest --test-dir build-maps-host --output-on-failure -j2` **12/12 통과**. 새 밑돌을 포함한 전체 지형에서 NPC/흔적/보스 및 네 출구의 실제 프레임 길찾기·왕복·자원 보존, SDL 상호작용/조작, 기존 전투/수련/UI/영웅·몬스터 렌더 검사를 재실행했다.

네 출구를 각각 844×390 및 1280×720으로 실제 SDL 출력해 확인했다. [844×390 네 출구 비교](waypoint-review.png). 배경 국소 변경 픽셀 검사 및 이정표 투명 알파 검증도 통과했다. 간판은 자연물 소품이며, 마법 포탈/광원 고리/자동 순간이동 효과는 추가하지 않았다.

로컬 준비 과정에서는 Windows 스크립트 실행 정책 때문에 파일 직접 실행이 거절되어, 정책을 변경하지 않고 같은 내용을 명령 인자로 실행했다. 초기 알파 검사 표본이 투명 여백에 있었으므로 실제 기둥 좌표로 교정해 다시 확인했다. 게임 실패를 숨기거나 테스트를 생략하지 않았다.

웹/단일 HTML 빌드는 PR CI 결과로 확인한다. 실제 브라우저 조작·iPhone/Android 기기·APK·장시간 성능은 이번 작업에서 실행하지 않았다. 버전 변경·main 병합·배포 없음. `GAME_BIBLE.md`는 없어 생성하지 않았다. 일반 적 재등장 등 다음 독립 작업은 진행하지 않았다.

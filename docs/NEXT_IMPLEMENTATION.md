# 첫 구현 작업 — 마을·사냥터 전환과 진행 상태 분리

작성일: 2026-10-25
기준: main `04cb6c502b27b21777eeeca7dbac91c9feae1618`
관련 기획: [컨셉 리비전안 v0.2](PALDOYADAM_CONCEPT_REVISION_v0.2.md)
상태: 다음 구현 작업의 제안 범위. 이 문서 작성으로 기능이 구현되거나 성장 규칙이 일괄 확정된 것은 아니다.

## 1. 첫 목표

**기존 1장에 마을 하나와 사냥터 하나를 구분하고, 왕복해도 현재 퀘스트·소지품·전투 진행이 정상적으로 유지되는 최소 기능을 만든다.**

이 기반 위에서 일반 적 재등장, 판매 재료·정혼주, 수련 트리, 토벌·증강을 차례로 추가한다. 먼저 맵과 상태의 경계를 정하면 새 성장 콘텐츠와 저장 기능에서 같은 상태 구조를 다시 만드는 일을 줄일 수 있다.

## 2. 현재 코드에서 확인한 결합

- `src/game.h`: 고정 월드 크기 2304×1536, `Game` 하나에 의뢰·주인공·백정·멧돼지 세 마리·드롭·물품·증강이 함께 있다. 맵 식별자가 없다.
- `src/world.c/h`: 한 배경 기준의 `WORLD_SOLIDS`·`WORLD_COVERS`와 공통 충돌·길찾기 상태를 사용한다.
- `src/draw.c`: 동일한 지도 텍스처와 고정 월드 범위로 배경·카메라·가림을 그린다.
- `src/main.c`: 목적지 이동·카메라·회복·재도전·수련장 진입이 현재 공간을 전제로 동작한다.
- 현재 의뢰는 흔적 두 곳 → 멧돼지 세 마리와 약재 → 약방 전달 → 이장 보고 → 백정 → 귀환·증강 → 윤겸으로 이어진다.
- 현재 숨겨진 허수아비 수련장은 게임 상태를 복사·복원하는 연습 기능이다. 기획안의 증강 보상형 토벌·수련과는 구분해야 한다.

## 3. 이번 구현에 포함할 범위

| 항목 | 최소 동작 |
| --- | --- |
| 공간 구분 | 마을·사냥터를 식별하고 각 공간의 범위·충돌·가림·출현 대상을 선택 |
| 왕복 통로 | 마을 출구와 사냥터 귀환 지점을 연결, 반대편의 유효한 위치에 도착 |
| 마을 대상 | 기존 NPC와 상점·회복·보고·전령 이벤트 배치 |
| 사냥터 대상 | 기존 흔적·멧돼지·약재·백정의 사건 흐름 배치 |
| 상태 보존 | 의뢰, 조사 기록, 물품·소지금, 장비·증강, 적 처치·드롭 회수·보상 기록 유지 |
| 화면·입력 | 전환 시 카메라를 도착 위치로 이동, 이전 공간의 목적지·공격 예약·효과·추격 정리 |
| 기존 예외 흐름 | 사망 귀환, 보스 재도전, 연습 수련장 복귀가 올바른 맵으로 연결 |

정식 신규 배경 원화 제작은 별도 미술 작업으로 둔다. 첫 기능 검증에는 임시 검토 배경을 사용할 수 있으나, 표시 공간과 실제 충돌·카메라 범위는 일치해야 한다.

## 4. 보존 규칙

- 정상 왕복만으로 체력·소모품·쿨타임이 공짜로 초기화되지 않게 한다.
- 흔적 조사, 약재 전달, 보상 수령, 백정 첫 소탕은 재입장으로 되돌리지 않는다.
- 이 단계의 기존 의뢰용 멧돼지 세 마리는 처치 상태를 유지한다. 일반 반복 사냥용 적과 재등장 규칙은 후속 독립 작업으로 설계한다.
- 의뢰용 약재의 회수·수량·반납 기록을 적 재생성과 분리해 중복 지급을 방지한다.
- 기존 죽음·회복·재도전의 결과를 보존하면서 도착 맵과 위치를 명시한다.
- 보스전·대화·메뉴·연습 수련 중 이동 허용 여부를 명확하게 정하고, 전환 입력의 중복 실행을 막는다.
- 길찾기·충돌 캐시는 맵을 바꾼 뒤 다른 공간의 데이터를 참조하지 않게 한다.
- 사냥터에서 연습 수련장에 들어갔다 나와도 원래 맵과 진행을 복원한다.
- 기본 공격·네 무공·스와이프 배치·판정·피해·성장 수치와 기존 세계관을 이번 분리 작업에서 임의로 바꾸지 않는다.

## 6. 완료 기준과 회귀 검증

1. 마을 → 사냥터 → 마을을 반복 왕복해도 위치·카메라·충돌·입력이 정상이다.
2. 체력·소지금·물품·장비·증강과 의뢰 상태가 정책대로 유지된다.
3. 기존 1장 의뢰를 처음부터 윤겸의 서신까지 진행할 수 있다.
4. 재입장·사망·재도전으로 의뢰 보상이나 약재가 중복되지 않는다.
5. 지도 전환 뒤 이전 적·드롭·길찾기 경로·공격 예약이 잘못 남지 않는다.
6. 숨겨진 허수아비 수련장의 격리·복원이 두 맵에서 모두 유지된다.
7. 기존 CTest와 새 전환 검사를 실행하고, SDL 화면 및 브라우저 왕복을 확인한다.
8. 실제 iPhone·Android의 회전·동시 터치·복귀는 실기기 확인 여부를 별도로 기록한다. 자동 검사 통과를 실기기 검증으로 표현하지 않는다.

첫 기능 단계에서 적용할 전환·재입장·복구 정책을 먼저 문서화하고 위 기준으로 확인한다. 마을·사냥터의 최종 미술 품질은 이 기능 검증의 완료 조건과 구분한다.

## 7. 이후 독립 작업

1. 일반 반복 사냥용 적의 재등장과 의뢰용 적·보상 분리.
2. 판매 부산물·성장 재화의 획득·소모 구조와 작은 수련 트리.
3. 짧은 토벌에서 증강 선택·종료 후 보상 보존 시험.
4. 증강 구성·무기 네 계열의 단계적 확장.

저장·이어하기는 초기 맵·의뢰·재화 상태 구분에 맞춰 별도 작업으로 설계한다. 장기 진행 보존이 필요한 파밍·수련 확장 전에 도입하며, 첫 맵 분리 완료를 영구 저장 구현으로 취급하지 않는다.

각 독립 작업은 결과 검토 후 다음 범위로 진행한다. 슬롯 수·정혼주 명칭·드롭률·트리 비용·증강 영구화 규칙은 리비전안의 제안·미정 표시를 유지한다.

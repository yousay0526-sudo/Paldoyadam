# 마을·솔바람재·탐식굴 연결 — 2026-10-27

사용자가 배경 세 장을 승인하고 적용·다음 단계를 요청하여, 원화 설치와 세 지역의 왕복을 한 작업 단위로 구현했다. 기준 main은 `04cb6c5`, 앞선 원화 기록은 PR #46이다. 원화 프롬프트는 [배경 제작 기록](BACKGROUND_MAPS_20261027.md)에 보존한다.

## 플레이 동작

| 지역 | 출입과 역할 |
| --- | --- |
| 마을 | 북쪽 문 → 솔바람재, 동쪽 길 → 탐식굴. 기존 이장·대장간·약방·주막·전령은 이곳에 있다. |
| 솔바람재 | 아래쪽 귀환 지점 → 마을 북문. 기존 의뢰용 멧돼지 세 마리·흔적 두 곳·약재 드롭을 배치한다. 보스는 표시하거나 시뮬레이션하지 않는다. |
| 탐식굴 | 아래쪽 귀환 지점 → 마을 동쪽 길. 백정은 이 동굴에 표시하며 기존 의뢰 단계에서 접근할 때 대화와 전투를 시작한다. |
| 비밀 수련장 | 기존 배경·지형·허수아비를 별도로 보존한다. 세 지역 어디에서 들어가도 원래 지역·위치·진행을 복원한다. |

출구 원 근처에서 **기존 상호작용 버튼 또는 Space**를 사용한다. 바깥 경계에 닿는 자동 전환을 추가하지 않아, 이동키를 누른 채 연속 왕복하지 않는다. NPC 대화·상점·입력·공격/네 무공 수치와 타이밍·줌·가로 모드 규칙은 보존한다.

일반 의뢰용 멧돼지는 기존처럼 흔적 두 곳 조사 후 활성화된다. 입장할 때마다 새 적·약재·보상을 생성하지 않는다. 반복 사냥용 일반 적과 재출현은 다음 독립 작업이다.

## 전환과 보존

- 정상 왕복은 체력·출혈·소모품·소지금·장비·증강·쿨타임·의뢰·조사·처치·드롭 회수 상태를 보존한다.
- 화면 전환 때 공격/무공/예약 입력·목적지·이동 속도·밀림·이펙트·카메라 흔들림을 정리하고, 카메라와 보간 위치를 도착 지점에 맞춘다. 살아 있는 적은 남은 체력을 유지한 채 자기 시작 위치에서 대기한다.
- 사냥터 드롭은 해당 지역에서만 자석 이동·나이·회수를 계산한다. 마을·동굴에서 좌표가 우연히 가까워도 다른 지역의 드롭이 움직이거나 지급되지 않는다.
- 전투 의뢰 진행 중, 대화·메뉴·사망·연습 수련 중에는 출구 이동을 막는다.
- 사망 귀환은 마을, 보스 재도전은 탐식굴이다. 기존 회복·보스 초기화 규칙을 유지한다.
- 서로 다른 맵을 왕복할 때 길찾기 캐시 키에 맵 ID와 몸 반경을 포함한다. 게임은 기존처럼 단일 스레드의 활성 지형을 사용하고, 지형을 사용하는 게임 진입 함수에서 소속 맵을 선택한다.
- 기존 지형 다각형과 원래 `assets/village.png`는 수련장에 보존했다. 새 맵은 `src/maps.c`의 독립 충돌·가림 표를 사용한다.

## 원화와 지형

승인 PNG는 `assets/maps/village.png`, `solbaramjae.png`, `tamsikgul.png`에 원본 바이트 그대로 설치했다. 모두 1536×1024 RGB PNG이며 월드 크기는 기존 2304×1536이다. 크기·원본 일치·SHA-256과 출처는 [provenance.json](../art/maps/provenance.json), 원화 픽셀 기준 수동 경계는 [layout.json](../art/maps/layout.json)에 기록했다.

탐식굴의 혈흔 없는 포식 흔적과 오른쪽 아래 작은 베어 먹은 사과는 원화 그대로다. 캐릭터·몬스터를 PNG에 합성하지 않았다. 새 그림에 맞춰 건물·암벽·동굴 벽의 충돌과 주요 지붕/수목 가림을 작성했으며, 전체 맵을 정확한 물리 메시로 자동 복원했다는 뜻은 아니다.

## 실제 검증

Windows, Zig 0.14.1 / Clang 19.1.7, SDL 2.32.10, 네이티브 CMake 전체 빌드와 **CTest 12/12 통과**.

- `map_travel`: 실제 프레임 이동으로 모든 NPC·양쪽 출구·사냥터 목표까지 길찾기, 반복 왕복과 맵별 캐시, 자원/쿨타임 보존, 의뢰 전체 흐름, 보상 중복 방지, 마을 귀환·동굴 재도전·세 맵의 수련장 복귀.
- `map_backgrounds`: 실제 텍스처 로드와 맵별 화면 차이, 마을의 잡몹·일반 사냥터의 보스 표시 차단, 동굴 보스 표시. 전체 맵 SDL 출력도 별도 저장했다.
- 기존 게임·충돌/슬라이드·전투·피드백·수련·SDL 조작·모바일 크기 UI·주인공/몬스터 렌더 검사를 실행했다. 기존 좌표 기반 회귀 fixture는 보존한 원래 지형을 명시적으로 선택한다. 새 실제 맵은 별도 검사에서 처음부터 `game_reset`으로 검증하므로 옛 fixture 통과를 새 맵 진행 검증으로 대체하지 않는다.
- SDL 입력 검사에 실제 Space·상호작용 액션으로 마을↔두 사냥터 왕복, 이전 목적지·공격 누름·카메라 상태 정리를 추가했다.
- 세 지역을 844×390·1280×720, 보스전과 수련장을 844×390으로 실제 실행 출력했다. 별도 전체 맵 출력 세 장과 충돌 오버레이를 육안 검토했다.
- [최종 CTest 로그](map-validation.txt). 웹 빌드 소스 목록에 `src/maps.c`를 추가했다.

## 발견한 문제와 복구

1. 원본 전송 도우미가 실행 환경의 네트워크/Windows 확장 속성 차이로 실패했다. 승인된 원본을 식별한 뒤 전송 경로를 복구하고 NTFS 파일 메타데이터를 보존했다. 새 그림을 다시 생성하거나 승인 그림을 재구성하지 않았다.
2. 로컬 CMake 실행 진입점·Zig 정적 라이브러리 명령 설정을 바로잡았다. 이 설정은 무시되는 로컬 build 폴더에만 있다.
3. 기존 사망 회귀 검사가 회복 후 같은 맵에 남는 옛 전제를 사용했다. 마을 귀환을 확인한 뒤 역사적 전투 fixture를 명시적으로 선택하게 고쳤고, 실제 맵의 귀환·재입장은 새 검사에서 다룬다.
4. 전체 맵 시각 검토에서 마을 중앙 소나무 군락의 충돌 누락을 찾아 추가하고 왕복 검사를 다시 실행했다.
5. 다른 맵에서 드롭 자석 시뮬레이션이 계속되는 결함을 추가 검사로 실제 실패 재현했다. 소속 맵 가드를 추가한 뒤 전체 CTest 12/12를 다시 통과했다.

## 남은 범위

브라우저 실행·실제 iPhone/Android 터치·APK·ASan/UBSan·장시간 메모리/성능은 이번 로컬 검증에서 실행하지 않았다. 원화 경계의 세밀한 가림과 이동 체감은 사용자 플레이 검토 대상이다. PNG 세 장은 약 10.74 MiB이며, 선로딩하는 추가 RGBA 텍스처는 약 18 MiB다.

## 설정표와 기대 수익

정본: `src/game.c`의 `MATERIALS[]` (이름·용도·확률·수량·단가). 하나의 배타적 0..99 추첨이다. 두 재료를 따로 추첨하지 않는다.

| 결과 | 판정 구간 | 확률 | 수량 | 개당 매각가 | 처치당 기대 매각 수익 |
|---|---|---:|---:|---:|---:|
| 가죽 조각 | 0..34 | 35% | 1개 | 3문 | 1.05문 |
| 뼈 조각 | 35..54 | 20% | 1개 | 2문 | 0.40문 |
| 재료 없음 | 55..99 | 45% | 0 | 0 | 0 |
| 재료 합계 | — | 55% | 최대 1개 | — | **1.45문** |
| 기존 즉시 엽전 + 재료 | — | — | — | — | **9 + 1.45 = 10.45문** |

상한 미도달·전량 회수/판매 가정의 초기 시험값이며, 손맛·장시간 경제 균형은 미검증이다. xorshift32 값을 100구간으로 축소하는 정수화 오차는 32비트 단위이며 표의 수익은 근삿값이다. 기존 수치를 함께 조정하지 않는다.

| 기존 물품 | 유지 가격 | 기존 9문만으로 필요한 처치 | 10.45문 기대 수익으로 환산 |
|---|---:|---:|---:|
| 단련한 환도 | 60문 | 6.67회 | 5.74회 |
| 누비 갑옷 | 45문 | 5회 | 4.31회 |
| 탕약 | 12문 | 1.33회 | 1.15회 |
| 지혈산 | 8문 | 0.89회 | 0.77회 |
| 국밥과 휴식 | 10문 | 1.11회 | 0.96회 |

환산은 시작 소지금·퀘스트 보상·치료 비용을 제외한 비교이며, 필요한 정수 처치 수 보장은 아니다. 100처치 기준 기존 900문 + 기대 매각 145문 = 1,045문(약 16.1% 증가), 6처치 기대 62.7문이다.

## 드롭 확정과 보존 정책

- 일반 멧돼지의 체력이 처음 0이 된 같은 호출에서 기존 9문·재생성 시계·PRNG 한 번 진행·결과 생성을 처리한다. 비치명타·이미 죽은 적·의뢰 적·허수아비는 재료 추첨을 하지 않는다. 확률 실패·상한 도달도 확정 결과다.
- PRNG 상태는 저장한다. 처치 상태·소지금·확정된 바닥 재료가 한 기록에 들어가므로 불러오기 자체로 재추첨하거나 중복 지급하지 않는다. 강제 종료로 마지막 약 1초를 잃으면 그 전체 상태가 이전 기록으로 돌아가며, 재료/엽전만 따로 남지 않는다.
- 재료 바닥 풀은 **최대 32더미, 종류별 16더미**다. 적 슬롯과 의뢰 약재 배열로부터 독립적이다. 적 재생성·같은 슬롯 재사용이 이전 드롭을 덮어쓰지 않는다.
- 종류별 16더미가 차면 이후 같은 재료는 **그 종류의 첫 미회수 더미 수량에 합산**한다. 기존 위치·수량을 보존하고 “기존 바닥 더미에 합산” 안내를 띄운다. 새 처치 위치에는 별도 더미가 생기지 않는다. 다른 종류를 위한 16자리는 항상 별도다.
- **유지 시간 제한 없음.** 시간·메뉴·다른 지역·마을 왕복·새 사냥 회차·사망 회복·이어하기로 사라지지 않는다. 솔바람재에 돌아와 다시 회수할 수 있다. 새 여정 확정 시에는 여정 전체와 함께 초기화된다.
- 종류별 **가방 + 바닥 합계 최대 9,999개**. 이 한도에 도달하면 해당 재료의 새 생성은 멈추고 안내한다. 기존 재료를 삭제하지 않고 9문 지급·재생성은 유지한다. 일부 매각하면 다시 생성 가능하다.
- 저장 중 잘못된 바닥 좌표만 발견되면 도달 가능한 첫 일반 멧돼지 출현 지점으로 보정한다. 잘못된 수량·시계·PRNG 0은 전체 기록을 거부한다. 수량을 임의로 보상하지 않는다.

## 회수·가방·판매

- 약재와 동일한 공통 자석 루틴: 바닥 0.7초 대기, 반경 156, 70→220 속도, 0.25초 이상 흡수 후 거리 16에서 확정, 벽 차단. 메뉴·대화·수련·타 지역에서는 멈춘다. F는 기존 반경 70 안의 보조 회수다.
- 재료 회수는 가방 수량 증가와 바닥 더미 제거를 같은 함수에서 한 번 처리한다. 의뢰 약재 수·약재 드롭 존재/회수·퀘스트 단계에 접근하지 않는다. 바닥 더미 수량 전체를 한 번에 중첩한다.
- 획득 안내는 종류별로 합산해 기존 전투·퀘스트 알림이 끝난 뒤 같은 한 줄 자리에서 표시한다. 별도 HUD 패널을 만들지 않으며 자동저장 안내 배치를 보존한다. 안내 대기는 표시 전용이라 저장하지 않는다.
- 가방 ‘기타’: 두 재료만 일반 재료로 표시하며 ‘의뢰품’ 약재, ‘소비’ 탕약/지혈산, ‘장비’와 구분한다. 보유 수량·대장간 매각 용도·개당 단가를 표시하고 사용/장착 버튼을 만들지 않는다.
- 기존 대장간의 구입 탭에 환도·갑옷을 유지하고 재료 매각 탭을 추가한다. 재료 선택·보유량·단가·1개/전부 판매 수량과 총액을 표시한다. 새 NPC 없음. PC 마우스·모바일 공통 버튼 경로, 기존 키 조작·회복·장착 유지.
- 매각 허용 목록은 전용 `Material` 경로의 가죽·뼈뿐이다. 의뢰품·장비·소모품 키를 매각 UI에서 만들지 않는다. 실제 본편 마을의 대장간·거리·메뉴·수량·소지금 범위를 매 호출 다시 확인한다.
- 양수 수량·재고·기존 소지금 저장 한도 1,000,000문을 확인한 뒤, 곱셈 전 나눗셈으로 넘침을 검사한다. 실패·취소·닫기는 재고·돈을 바꾸지 않는다. 성공은 재료 차감과 엽전 증가를 하나의 거래로 처리한다. 연속 클릭도 남은 재고를 다시 확인하며 전부 판매 뒤 잔액 0을 다시 지급하지 않는다.

## 저장·이행·수련장

v4는 **928바이트**, 작업 버퍼는 1,024바이트다. v3의 기존 필드 뒤에 재료 보유량 2개, PRNG, 32더미의 수량·위치·대기/흡수 시간을 추가한다. 바닥 종류는 종류별 풀 위치로 결정한다. [상세 형식](SAVE_SYSTEM.md).

v1(216)·v2(224)·v3(276) 진행을 보존하며 새 재료와 바닥 풀은 0, PRNG는 비제로 기본값으로 이행한다. v3의 처치된 적에 재료를 소급 생성하지 않는다. v1/v2의 기존 #52 사냥 이행 규칙은 유지한다. 다음 정상 저장은 v4이고, 과거 게임으로 v4를 읽을 수 없다. 정식 게임 버전 0.8.0은 바꾸지 않는다.

수련 입장 전 본편 상태를 보관하고, 허수아비 타격은 본편 드롭·재료·엽전을 생성하지 않는다. 수련 저장을 거부하고 복귀 시 원래 본편 바닥·가방·소지금·PRNG를 돌려놓는다.

- `native_economy_write` → `native_economy_restart`: 초기 fixture만 설치한 뒤 제품 main 루프에 SDL 마우스/키 이벤트를 보내 실제 공격→자석 회수→기타 탭→길을 걸어 마을 귀환→대장간→1개 판매→타이틀 이어하기→별도 OS 프로세스 재실행을 검사한다. 테스트 프로필만 사용하고 실행 중 Game을 직접 수정하지 않는다.
- 기존 1장 전체 진행, 반복 사냥, 전투·입력·상점·소모품·장착·가방·자동저장 회귀를 포함한다. UI 검사는 PC/터치 경로, 432×270~1280×720, 0/7/9,999개에서 판매 버튼 크기·범위·비겹침, 재판매 차단을 확인한다.
- 기존 메인 저장 검사에서 일부 실행이 잔여 슬롯을 감지해, 테스트 정리 반환값·SDL 시작 전 빈 저장소 단정·저장 경로 진단을 추가했다. 단독/최종 전체 재검사는 통과했고 정확한 환경 상태 간섭 원인은 확정하지 못했다. 제품 저장 경로/동작은 바꾸지 않았다.
- 실제 SDL 소프트웨어 화면 `sell` 432×270·844×390, `bag-materials` 844×390을 생성해 빈 이미지 칸과 수량·단가·판매 총액을 시각 확인했다.
- `tests/browser_economy.cjs`와 읽기 전용 테스트 훅을 추가했다. 초기 저장 fixture를 설치한 뒤 실제 Chromium 입력·새로고침·프로세스 재실행·수련 저장 격리를 검사하는 절차다. **이 환경에서는 Chromium이 socket 생성 권한 오류로 시작하지 못해 시나리오는 미실행**이다. JS 문법 검사만 통과했다. 브라우저 통과라고 표현하지 않는다.
- 로컬 Emscripten SDK 실행은 설치된 clang의 SIGSEGV로 중단됐다. 웹 빌드 판정은 PR CI 결과로 따로 확인한다. 실제 Windows 창/GPU, iPhone·Android 터치·백그라운드/APK, Safari/Firefox, 장시간 경제/성능은 미검증이다. LeakSanitizer는 /proc 작업 접근 오류가 있어 누수 검증을 별도로 남긴다.

재현:

```sh
cmake -S . -B build-economy -DCMAKE_BUILD_TYPE=Debug
cmake --build build-economy --parallel 2
ctest --test-dir build-economy --output-on-failure
cmake -S . -B build-economy-asan -DPALDO_SANITIZE=ON
cmake --build build-economy-asan --parallel 2
ASAN_OPTIONS=detect_leaks=0 ctest --test-dir build-economy-asan --output-on-failure
python scripts/build_web.py --test-hooks --output dist/economy-test
node tests/browser_economy.cjs dist/economy-test build-economy/browser-qa build-economy/economy-start.sav
```

브라우저 검사에는 Playwright·Chromium이 필요하다. `PALDO_BROWSER`로 설치된 실행 파일을 지정할 수 있다. 테스트 훅은 `PALDO_WEB_TESTING` 빌드에서만 포함되며 제품 빌드는 제외한다.

**main 병합·자동 병합·Pages 배포·정식 버전 변경 없음.** 다음 독립 작업은 사용자 승인 후 진행한다. `GAME_BIBLE.md`가 저장소에 없어 새로 만들지 않았다.

# 승인된 몬스터 8방향 연결 · 2026-10-21

사용자가 원화 검토 후 “진행 해줘”로 게임 연결을 승인했다. 독립 브랜치 `graphics/monster-eight-direction-pass1-20261021`, PR #32에서 이어 작업한다. 원화 준비 기록은 [MONSTER_MOTION_ART.md](MONSTER_MOTION_ART.md), 후속 장 후보는 [MONSTER_ROSTER_RESEARCH.md](MONSTER_ROSTER_RESEARCH.md)에 남긴다. 새 몬스터·장·AI 패턴을 추가하는 단계는 아니다.

## 표시와 보존 범위

- 연결 기준 main `649b02f087e7a016378756ec1ac72861c997d30b`. 원화 이후 추가된 넉백/경직, 이동 가감속, 몸 겹침 방지·동시 준비 제한, 고정 1/60초 시뮬레이션/위치 보간, 경사 벽 미끄러짐과 공통 전투 수치를 합쳐 보존했다.
- 돼지: 정지·걷기·엄니 공격. 백정: 정지·걷기·기존 큰 내려찍기. N/NE/E/SE/S/SW/W/NW의 독립 원본을 선택하며 수평 반전하지 않는다.
- `Enemy.facing`과 `walking`은 **표시용 필드**다. `move_toward()`의 지형 충돌 해결 후 실제 변위에서 방향을 기록한다. 밀림/몸 분리 이동을 걷기 거리로 세지 않으며 정지 후 마지막 방향을 유지한다. 공격 준비를 시작할 때 기존 `angle`과 같은 방향을 기록한다. AI·타격 계산은 이 새 필드를 읽지 않는다.
- 걷기는 기존 `stride`를 사용한다. 52 월드 단위마다 네 포즈를 한 바퀴 돈다. 이동 중에만 보폭에 따른 기존 출렁임/눌림을 적용한다. 멈췄는데 이전 보폭의 출렁임을 유지하지 않는다.
- 준비 시간의 전/후반에는 포즈 0/1, 실제 타격 상태에서 2, 회복에서 3이다. 돼지는 `AI_RECOVER` 진입 첫 0.15초가 타격 포즈/돌진 연출, 백정은 `AI_SWING` 0.2초가 타격 포즈다. 무공으로 준비가 끊긴 돼지의 0.6초 회복에는 타격 그림을 재생하지 않는다. 공격 도중에는 기존 고정 `angle`로 방향을 선택하므로 주인공이 옆으로 이동해도 시트가 돌아가지 않는다.
- 현재 백정 AI에는 큰 공격 한 가지만 있다. **짧은 평타 후보는 `art/monsters/prepared/butcher-attack-8dir-v1.png`에 보존하고 실행본으로 설치하지 않는다.** 두 번째 피해/쿨타임/공격 규칙을 임의로 만들거나 큰 공격 중 가로베기로 바꾸지 않았다.
- 기존 피격 빛/눌림, 쓰러짐 회전·가라앉음·알파 소멸, 그림자·발 먼지·충격 고리·타격 파편을 유지한다. 그림은 발 기준점을 중심으로 변형한다. 가림은 회전한 시트 네 모서리를 포함한 사각 범위를 기존 지붕/수목 폴리곤에 넘겨 칼/발/넘어진 몸을 함께 복원한다. NPC·주인공은 기존 가림 범위를 그대로 쓴다.
- 전투 피해·타이밍·거리·각도·시야·넉백·경직·입력 버퍼·콤보·이동·수련·NPC·퀘스트·맵·배포 설정·버전은 이 연결 작업에서 변경하지 않는다. 피/혈흔 이펙트와 새 그림을 추가 생성하지 않았다. 주인공의 붉은 허리띠와 모든 기존 PNG를 보존한다.

## 실행 에셋 계약

`python scripts/prepare_monster_assets.py` 뒤 `python scripts/install_monster_assets.py` (Pillow)를 실행한다. 설치는 원본/후보를 덮어쓰지 않고 승인된 여섯 PNG의 바이트 복사본을 `assets/monsters/`에 놓으며, 방향별 배율 표 `src/monster_atlas_data.h`와 설치 해시 `art/monsters/runtime.json`을 생성한다.

| 종류 | 설치 파일 | 크기·배열 |
| --- | --- | --- |
| 돼지 정지 | `boar-idle-8dir-v1.png` | 768×384, 4×2 방향 순 |
| 돼지 걷기·공격 | `boar-walk-8dir-v1.png`, `boar-attack-8dir-v1.png` | 각각 768×1536, 4열 포즈×8행 방향 |
| 백정 정지 | `butcher-idle-8dir-v1.png` | 768×384, 4×2 방향 순 |
| 백정 걷기·내려찍기 | `butcher-walk-8dir-v1.png`, `butcher-skill-8dir-v1.png` | 각각 768×1536, 4열 포즈×8행 방향 |

모두 192px 정사각 셀과 발 `(96,176)`을 사용한다. 기본 표시 셀은 돼지 60, 백정 110 논리 픽셀이고 넓은 포즈의 `draw_scale_compensation`을 함께 곱한다. 정지/걷기의 가시 높이는 약 42.5/82.5로 기존 약 41.5/82.5와 맞췄다. 방향별 길이·엄니·칼 실루엣은 다르므로 외곽 너비가 모두 같지는 않다. 기존 적/NPC와 같은 선형 샘플링을 쓴다. 로더는 각 시트의 치수를 검사하고 실패 시 이미 만든 텍스처를 해제한다.

추가 상주 RGBA 텍스처는 **21,233,664바이트(20.25MiB)**다. 이는 여섯 시트의 픽셀 합계이며 드라이버/디코딩 임시 메모리나 다운로드 총량 측정은 아니다. 웹과 Android는 기존 `assets/` 묶음 경로를 사용하므로 별도 사전 로딩 목록을 만들지 않는다. 실제 휴대폰 메모리/성능 측정은 남아 있다.

## 검증

- Windows, CMake 4.4.4 / Ninja 1.13.2 / Zig 0.14.1(Clang 19.1.7) / SDL 2.32.10. 전체 CMake 빌드와 CTest **10/10 통과**: gameplay, world_navigation, isolated_training, directional_combat, hit_feedback, native_render, player_controls, responsive_ui, hero_animation, monster_animation.
- `tests/test_game.c`: 양 몬스터의 8방향 실제 이동과 속도 보존, 정지 방향 유지, 메뉴/히트스톱 동결, 돼지 귀환 방향 검사. 기존 전투/퀘스트 검사와 함께 통과했다.
- `tests/test_monster_render.c`: 1/2/3배의 실제 SDL 출력과 기대한 원본 셀·발 기준점·배율을 픽셀 단위 비교. 정지/네 걷기 포즈/준비 전후반/마지막 준비 틱/타격/회복/경직, 공격 중 이동 방향 무시, 출력 범위, 쓰러짐/소멸, 피격 후 텍스처 색·알파·블렌드 복원 검사. 마지막 준비·경직·넘어짐 경계 보강 후 이 검사를 다시 실행해 **13,290,216개 조건 통과**.
- 영웅 렌더링 7,065,056, 게임 714, 지형 157, 수련 1,578, 방향 전투 753, 피드백 159, SDL 입력 911, UI 1,842개 조건과 native_render 통과. 이전 원화 단계의 CI 결과를 이번 결과로 재사용하지 않았다.
- `python tests/test_monster_assets.py`: **2/2 통과**. 기존 원본/176셀 검사 외에 설치본 6개가 후보와 바이트 일치하고 C 배율 표가 메타데이터와 일치함을 확인한다.
- 로컬 전체 구성에는 작업 폴더의 Zig 도구체인·아카이버 규칙·SDL import library를 사용했다. 초기 구성 완료 전 빌드를 요청해 캐시 부재로 중단됐으나, 구성 종료 확인 후 다시 빌드해 복구했다. 기존 SDL 검사 파일의 `SDL_MAIN_HANDLED` 빈 선언과 로컬 구성의 값 1 선언 사이 재정의 경고가 있었으며 제품 코드 경고는 없었다. 저장소 빌드 설정에 이 로컬 우회를 넣지 않았다.

- 실제 SDL 게임 수련장 432×270/844×390/1100×650 출력 성공. 시간 카운터만 고정한 검증 실행본으로 기준 main과 후보의 11장면, 전후 총 22장을 생성했다. 마을·상점·수련·지붕·수목·skill0/2/3은 **전체 픽셀 일치**. boss 차이 경계 `(484,96)..(583,203)`, recover `(515,89)..(791,290)`, attack3 `(449,89)..(725,290)`는 적들 주변에만 있다. [실제 게임 전후](monster-gameplay-comparison.png)는 왼쪽 기준 main, 오른쪽 후보다. 공격 장면의 주인공·검 궤적·UI는 그대로다.
- [SDL 모션](monster-eight-direction-sdl.gif)은 실제 `gfx_enemy()`의 네 표시 키를 8방향으로 출력해 묶은 자료다. 프레임 간격은 리뷰용이며 게임 전체 이동 속도/공격 타이밍을 대표하는 동영상이 아니다. 알파·칼/엄니·발·몸 크기를 밝은 배경에서 검토했다.
- 지붕/수목의 경계에서 양 몬스터 8방향 총 32장 출력과 [가림 리뷰](monster-cover-review.png)를 시각 검토한다. 첫 검증 fixture에서 흔적 완료를 설정하지 않아 멧돼지가 비활성인 것을 발견해, 완료 플래그를 켜고 부분 가림이 드러나는 위치로 수정하여 다시 출력했다. 제품의 퀘스트 조건을 변경한 것이 아니다.

CI 결과는 PR에서 별도로 확인한다. 실제 iPhone/Android/APK·새 시트의 브라우저 표시·장시간 메모리·정교한 발 미끄러짐 제거는 별도 확인 대상이다. GAME_BIBLE.md는 없어 생성하지 않았다. 이번 승인에 main 병합·자동 병합·Pages 배포 권한을 포함하지 않는다.

# 팔도야담 에셋 제작 표준 · 1단계 검토안

제작자는 먼저 대상 동작과 기준 PNG 한 셀을 고른다. 그 셀의 인물 비례·카메라·발 위치를 고정하고, 바뀌는 부위만 그린다. 완성본은 원본 크기와 게임 표시 크기에서 각각 검수한다. 이 문서의 실행 규격은 2026-11-12에 확인한 [main 1ced1a0](https://github.com/yousay0526-sudo/Paldoyadam/tree/1ced1a0776eab2e0d9e7619bdad02714d48e6bfa) 기준이다. 후반의 납품·검수 절차는 새 원화에 적용할 제안이다.

## 1. 현재 주인공의 실행 규격

모든 셀은 192×192px, 파일은 투명 RGBA PNG다. 행 우선으로 왼쪽 위를 0번으로 센다. 아래 표시 상자는 카메라 확대 전 논리 좌표이며 상자 전체에 투명 여백도 들어간다. `ACTOR_SCALE=1.4`를 적용하고 화면 높이에 따른 월드 줌은 별도로 적용한다. [렌더러 gfx_load·gfx_hero](../src/draw.c) · [방향 열거형·확대율](../src/draw.h) · [동작 상수](../src/game.h) · [프레임 선택](../src/game.c)

| 동작과 실행 파일 (`assets/`) | 시트와 프레임 선택 | 발 기준점과 표시 상자 |
| --- | --- | --- |
| 정지 · `warrior-idle-8dir-v1.png` | 768×384, 4×2 한 장. N·NE·E·SE / S·SW·W·NW 순으로 방향당 한 자세 | (96,176), 56×1.4 = 78.4 |
| 걷기 · `warrior-walk-{n,ne,e,se,s,sw,w,nw}-v1.png` | 같은 규격 8장. **한 장이 한 방향**의 연속 8프레임(0~7). 실제 이동거리 112 월드 단위마다 한 주기 | 정지와 같음 |
| 기본 공격 · `warrior-attack-v1.png` | 576×384, 3×2 한 장. 준비·들기·타격·후속·회수·복귀 6셀. 0.42초를 6등분, 타격 0.14초 | 아래 프레임별 기준점, 64×1.4×보정값 |

정지·걷기는 마지막 입력 방향 벡터를 북쪽부터 시계방향 45°씩 나누고 원화를 그대로 그린다. 영벡터와 비유한 값의 선택값은 S다. 공격·무공은 시작할 때 고정한 `attack_face > 0`이면 왼쪽 원화를 수평 반전한다. 움직이는 중에도 공격 원화가 우선한다. 따라서 정지·걷기의 오른손 8방향을 공격에서도 보장한다고 표기하면 안 된다. 무공 셀 재생 순서는 갈라베기·물러베기 `01123455`, 횡베기 `00123345`, 파고들기 `00123455`다. 물러베기 셀 1은 제작 때 왼쪽 기준으로 한 번 교정한 기록도 있다. [방향 가이드](HERO_DIRECTIONS.md) · [무공 준비 기록](../art/hero/techniques/preparation.json)

**기본 공격의 발 좌표**는 코드에서 512 단위의 셀을 기준으로 기록했다. 192px 셀에서 표시할 때는 두 좌표에 192/512를 곱한다.

| 셀 | 512 기준 (x,y) | 표시 크기 보정 |
| --- | --- | --- |
| 0 | (290,470) | 1 |
| 1 | (264,470) | 1 |
| 2 | (310,470) | 1 |
| 3 | (340,455) | 1 |
| 4 | (280,464) | 0.95 |
| 5 | (300,465) | 0.88 |

셀의 왼쪽 위가 (0,0), 오른쪽이 +x, 아래가 +y다. 셀 번호 i의 시트 원점은 `((i % 열수) × 192, floor(i / 열수) × 192)`다. 셀 안 발 좌표를 (u,v)로 놓으면 그림 상자의 왼쪽 위는 `화면상의 발 − (u/192, v/192) × 상자 한 변`이다. 반전할 때 x 비율만 `1 − u/192`로 바꾼다. 기준점은 그림을 놓는 위치다. 검 끝을 포함한 그림의 중심, 양발의 개별 관절, 충돌 반경과는 용도가 다르다.

**실측 예시.** 정지 SE는 셀 3이다. 시트 원점 (576,0), 셀 안 발 (96,176)이므로 시트 위 발은 (672,176)이다. 해당 셀에서 알파가 있는 영역은 (59,29)부터 오른쪽·아래 제외 경계 (138,177)까지다. 장비만 잘라 저장했다면 자른 사각형의 셀 안 원점을 함께 기록해야 같은 위치로 복원할 수 있다. [정지 시트](../assets/warrior-idle-8dir-v1.png) · [방향별 bounds·root·해시](../art/hero/directions/preparation.json)

**레이어의 현재 상태.** 필드에서는 몸·옷·손·환도가 그려진 한 셀을 선택한다. 일부 공격 셀에는 푸른 궤적까지 들어 있다. 엔진은 그림자, 회피 잔상·피격 번쩍임, 공격 궤적과 지형 가림을 별도로 그린다. 가방은 `warrior-v2.png`(138×138) 초상화를 쓰며, 구형 `warrior-walk-v1.png`(552×276)도 로드되지만 필드 걷기는 방향별 시트를 선택한다. 환도·갑옷 장착 상태는 게임 수치에 쓰인다. 슬롯별 외형과 프레임별 손·머리 좌표를 불러오는 경로는 현재 없다. [가방 표시](../src/main.c) · [기본 공격 원화](../assets/warrior-attack-v1.png)

## 3. 검수 순서와 보류 조건

1. **윤곽과 색.** 기준과 후보를 같은 발 위치·배율로 나란히 놓고 실제 표시 크기와 확대에서 본다. 흙빛 마을 배경에서 얼굴·깃·허리띠·손에 든 물체가 읽히고, 밝은 배경과 어두운 배경에서 반투명 가장자리에 테두리가 생기지 않는지 본다. 인물 그림에는 바닥 그림자를 구워 넣지 않는다.
2. **발 접지와 동작.** 각 방향의 정지→걷기 0~7→0→정지를 돌려 본다. 지지발과 떠 있는 발을 표시하고, 같은 지지 구간에서 밑창이 땅속에 잠기거나 옆으로 튀는 프레임을 기록한다. 먼 발을 가까운 발의 화면 y에 강제로 맞추면 원근이 깨진다. 공격은 각 셀의 고유 발점과 좌우 반전으로 준비→타격→회복→정지를 본다. 몸통과 팔의 무게 이동, 단단한 칼의 길이, 천 주름의 연속성을 함께 본다.
3. **손과 장착.** 부품 단독→빈 몸→착용 상태를 한 셀에서 번갈아 본다. 손바닥 안의 자루는 손가락 뒤로 숨고 칼날은 해당 자세의 앞·뒤 관계를 따른다. 모자 챙은 이마와 상투에, 바짓단·신발은 옷자락과 밑창에 맞춘다. 손·발 목표 좌표와 PNG에서 독립적으로 읽은 관찰 좌표를 함께 남긴다. 손이 보이지 않아 측정할 수 없는 프레임은 보류 사유를 적는다.
4. **겹침과 누락.** 분리 전후의 보호 영역을 겹쳐 원래 픽셀 변화를 확인한다. 앞/뒤 마스크의 합으로 전체 부품을 복원하고 중복·구멍을 확인한다. 빈 몸만 켜서 옛 칼날 잔류도 별도로 본다. 손가락 이중 그리기, 모자·칼끝 잘림, 재합성 차이가 있으면 해당 셀과 마스크를 고쳐 다시 비교한다.
5. **판정 기록.** 기술 통과·실패와 미술 승인·보류를 각각 기록한다. 파일·해시·좌표 통과만으로 붓질, 비례, 무게감, 다른 방향이나 동작까지 승인할 수 없다. 단일 포즈의 통과 범위를 납품 기록에 명시한다.

## 4. 검증 예제

저장소 루트에서 Python 3과 Pillow로 실행한다. 예제는 기존 PNG와 제작 JSON을 읽으며 출력 파일을 만들지 않는다. [검증 예제](examples/check_hero_atlases.py)

```sh
python docs/examples/check_hero_atlases.py
```

정상 출력은 `PASS: 102 runtime hero cells`이다. 14장 모두 형식·격자·셀별 투명 배경과 가시 픽셀을 검사한다. 준비 기록이 있는 13장은 SHA-256·프레임별 알파 경계·사방 4px 여백도 대조한다. 기본 공격은 같은 준비 JSON이 없고 실제 최대 알파도 셀별 253~254다. 발·손의 해부학적 위치와 화풍은 3절의 비교로 판정한다.

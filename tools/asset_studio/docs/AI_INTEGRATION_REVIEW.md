# AI 이미지 생성 연계 검토 (4차, 2026-11-12)

결론부터: **이번 4차는 네트워크를 쓰는 AI 기능을 넣지 않았다.** 대신 GPT 등에서 내려받은 원화를 스튜디오 안에서 로컬로 정리하는 흐름("GPT 원화 가져오기", 배경 제거, 키 맞추기, 발 맞추기)을 만들었다. 외부 서비스 연동은 아래 이유로 사용자 결정이 먼저 필요하다.

## 1. 지금 저장소의 AI 원화 흐름 (확인한 사실)

- 원화와 프롬프트가 함께 보관된다: `art/monsters/*-master.png` + `*-prompt.txt`, `art/hero/*-prompt.txt`, `art/hero/directions/eight-direction-prompt.txt` 등.
- 몬스터 걷기·공격 원화는 GPT가 그린 4×4 아틀라스(한 장에 4방향×4프레임, 두 장으로 8방향)이며, `scripts/prepare_monster_assets.py`가 자세를 골라(알파 연결 영역) 192 셀·발 96,176에 맞춰 넣는다. 반사·재채색·트위닝은 하지 않는다고 적혀 있다.
- 주인공 8방향도 원화 → `scripts/prepare_direction_assets.py` → `assets/`의 같은 흐름이다.

즉 "AI가 그리고, 사람이 고르고, 스크립트가 규격에 맞춘다"가 현재 방식이다. 스튜디오는 이 중 **규격에 맞추는 단계**를 GUI로 옮긴 것이고, 그리는 단계는 바꾸지 않았다.

## 2. 4차에서 만든 것 (네트워크 없음)

| 기능 | 하는 일 | 원본 |
| --- | --- | --- |
| GPT 원화 가져오기 (Ctrl+G) | 원화 한 장을 현재 방향·프레임에 넣고, 배경 제거 → 잡점 제거 → 키 맞추기(참고 레이어 또는 숫자) → 발 맞추기를 한 번에, 실행 취소 한 번 | 원본 파일과 프로젝트 사본은 그대로, 보정본은 `sources/`에 새 사본(`derived`에 무엇에서 어떻게 만들었는지 기록) |
| 배경 제거 | 네 모서리가 같은 색일 때, 가장자리와 이어진 그 색 영역만 투명하게. 그림 안의 같은 색은 남김. 경계 1px 부드럽게(선택) | 새 사본 |
| 잡점 제거 | 알파 1~4를 0으로 (검사·`preparation.json`의 `alpha_noise_cutoff`와 같은 기준) | 새 사본 |
| 발 맞추기 | 측정 바닥·발 중심을 그 프레임의 발 기준점에 맞춰 레이어 위치만 이동 (현재 칸 / 모든 방향·프레임) | 위치만 |
| 키 맞추기 | 선택 레이어의 그림 높이를 같은 칸 참고 레이어(예: 템플릿의 기존 실행 셀)와 같게, 발 위치 유지 (±1px) | 배율만 |

한계: 배경 제거는 단색(그라데이션·그림자 없는) 배경용이다. 복잡한 배경, 바닥 그림자, 반투명 효과(검기 등)는 사람이 외부 프로그램에서 정리해야 한다. 4×4 아틀라스 원화는 "시트에서 셀 가져오기"로 칸을 잘라 넣고 칸마다 보정한다. `prepare_monster_assets.py`의 자세 자동 선택(연결 영역)은 옮기지 않았다.

## 3. 검토한 연계 방식

| 방식 | 장점 | 문제 | 판단 |
| --- | --- | --- | --- |
| A. 지금처럼 브라우저의 GPT에서 그리고 PNG를 받아 가져오기 | 추가 비용·키 없음, 데이터가 스튜디오 밖으로 나가지 않음 | 프롬프트·원화 관리가 수동 | **채택 (4차 구현)** |
| B. 이미지 생성 API를 스튜디오에서 직접 호출 (예: OpenAI 이미지 API) | 프롬프트 → 원화 → 보정이 한 화면 | API 키 보관, 사용량 비용, **프롬프트와 참고 그림이 외부로 전송됨**, 생성물 이용 조건은 서비스 약관 확인 필요 | 보류. 이 프로젝트는 계정을 공유하며 "이곳의 데이터는 밖으로 나가지 않게"가 규칙이라, 사용자 승인 없이 넣지 않는다 |
| C. 로컬 생성 모델 (Stable Diffusion 계열 등) | 데이터가 밖으로 나가지 않음 | 수 GB 모델·GPU 필요, 모델마다 별도 라이선스(사용 제한 조항 포함 여부 확인 필요), 기존 그림체 유지에는 추가 학습이 필요할 가능성 큼 | 보류. 그림체 일관성 확인이 먼저 |
| D. 로컬 배경 제거 모델 (예: rembg) | 단색이 아닌 배경도 제거 | 모델 파일을 처음 한 번 내려받아야 함(약 수백 MB), 라이선스·배포 조건 확인 필요, 반투명 효과 경계 품질 미확인 | 후보. 승인 시 선택 플러그인으로 (기본 설치에 넣지 않음) |

라이선스·약관 항목은 이 문서 작성 시점에 원문을 다시 확인하지 않았다. 도입 전에 원문 확인이 필요하다.

## 4. 제안 (승인 후 별도 작업)

1. 프롬프트 메모: 에셋마다 사용한 프롬프트·원화 출처를 적는 칸, 저장소의 기존 `*-prompt.txt`를 참고로 보여 주기. (네트워크 없음)
2. 원화 아틀라스 자동 분할: 연결 영역으로 자세를 골라 칸에 넣는 `prepare_monster_assets.py` 방식을 GUI로. (네트워크 없음)
3. D(로컬 배경 제거 모델)를 선택 플러그인으로 시험.
4. B·C는 데이터 반출·비용·라이선스를 사용자가 정한 뒤에만.

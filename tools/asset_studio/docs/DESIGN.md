# 팔도 에셋 스튜디오 · 조사와 설계 (1차 MVP · 2차 · 3차 · 4차)

기준: main `1ced1a0` (2026-11-12). 이 문서는 툴의 설계 기록이다. 게임 에셋 규격 자체를 정하는 문서가 아니며, 규격은 저장소의 실제 파일과 GPT Work의 [에셋 제작 표준 검토안](https://github.com/yousay0526-sudo/Paldoyadam/blob/07c3b19/docs/ASSET_PRODUCTION_STANDARD.md)(브랜치 `docs/asset-production-standard-phase1`, 미병합)을 따른다. 그 표준과 다른 값이 생기면 툴이 아니라 표준 쪽 결정을 우선한다.

## 2. 아키텍처

```
tools/asset_studio/
  run_studio.py            진입점 (PySide6 없으면 설치 안내)
  requirements.txt
  paldo_studio/
    model.py               프로젝트·에셋·레이어·원본 데이터, JSON 저장, 스냅샷 실행 취소   (Qt 없음)
    imaging.py             PNG 읽기·정보, 잘라내기·배율(프리멀티플라이드), 합성, 내보내기     (Pillow+NumPy)
    checks.py              내보내기 전 검사 (정상/경고/오류)                                   (Qt 없음)
    game_specs.py          저장소 파일에서 규격 프리셋·시트 배치 읽기                         (Qt 없음)
    ui/main_window.py      좌(에셋·레이어) / 중앙(캔버스) / 우(속성·정보·미리보기) / 하(보기)
    ui/canvas.py           투명 격자, 확대·이동, 중심축·발 접지선, 드래그·키 이동, 기준점 찍기
    ui/dialogs.py          새 에셋, 시트 셀 가져오기, 검사 결과
  tests/                   test_core.py (Qt 없이), test_gui.py (offscreen 실제 창)
  scripts/capture_screens.py
  docs/                    이 문서, 화면 캡처
```

- **모델·이미지·검사는 Qt와 분리**했다. 같은 코드를 명령줄 일괄 처리나 CI 검사에 재사용할 수 있고, Qt 없이 테스트된다.
- **원본 보존**: 가져오기는 프로젝트 `sources/`에 복사(SHA-256 기록)만 한다. 레이어는 원본 + 잘라낸 영역 + 위치/배율/기준점의 *설명*이며 픽셀을 바꾸지 않는다. 내보낸 PNG는 그 설명에서 매번 다시 만든다.
- **실행 취소**: 프로젝트 JSON 스냅샷(픽셀 없음, 수 KB). 같은 입력칸 연속 변경·한 번의 드래그는 한 단계.
- **규격은 읽기만**: 프리셋 값은 저장소 파일에서 읽고, 읽지 못하면 해당 프리셋을 숨기고 이유를 표시한다. 툴 안에 새 규격을 만들어 넣지 않았다.
- **확장 계획(2차 이후, 아직 구현 안 함)**: 에셋에 방향·프레임 필드를 더해 8방향·애니메이션으로 넓히고 레이어별 프레임 순서표를 둔다. 프로젝트 파일은 형식 버전(`paldo-asset-studio/1`)을 기록하고, 없는 필드는 기본값으로 읽으므로 필드를 추가해도 1차 프로젝트를 그대로 열 수 있게 할 계획이다. AI 연계·배경 제거·파츠 분리는 가져오기 앞에 붙는 플러그인(입력 PNG → 출력 PNG + 기록)으로 넣는다.

### 데이터 형식 (요약)

```json
{
  "format": "paldo-asset-studio/1",
  "name": "…",
  "sources": [{"id", "file": "sources/<sha12>-<이름>.png", "original_name", "original_path", "sha256", "width", "height", "mode"}],
  "assets": [{
    "id", "name", "kind": "character|npc|monster|weapon|equipment|item",
    "width", "height", "anchor": [x, y], "preset", "export_name",
    "layers": [{"id", "name", "source", "crop": [x, y, w, h] | null, "x", "y",
                "pivot": [x, y] | null, "scale", "smooth", "slot", "visible", "opacity", "locked",
                "view", "group", "frame"}],
    "directions", "hidden_groups", "combos", "tolerances",
    "frames", "fps", "frame_anchors": {"<프레임>": [x, y]}, "sheet_layout", "sheet_columns"
  }]
}
```

`layers`는 아래(뒤)→위(앞) 순서. `pivot`은 배율 적용 전 레이어 픽셀 좌표라 배율을 바꿔도 같은 지점을 가리킨다. 부위가 `reference`인 레이어는 화면에 반투명으로만 보이고 내보내기에서 빠진다(이전 그림과 겹쳐 비교하는 용도).

## 5. AI 원화 흐름에서 1차가 맡는 부분

GPT 원화 PNG 다운로드 → **가져오기 → 기준 셀(참고 레이어)과 겹쳐 배율·위치·기준점 맞추기 → 검사 → 내보내기**까지가 1차로 가능하다. 배경이 있는 원화는 "투명 픽셀 없음" 경고가 뜨며, 배경 제거는 4차 플러그인 범위다. 단일 정면 원화로 8방향·전투 동작이 자동 생성된다고 가정하지 않는다.

## 6-1. 2차 구현 기록 (2026-11-12, 기준 main `0805c14`)

- 모델: `Asset.directions`(빈 목록 = 단일 보기), `Layer.view`(방향 코드), `Layer.group`(장비 묶음), `Asset.hidden_groups`, `Asset.combos`(조합 이름 → 켜진 묶음), `Asset.tolerances`. 모두 기본값이 있어 1차 프로젝트 파일을 그대로 연다(형식 문자열은 `paldo-asset-studio/1` 유지).
- 합성·검사·내보내기는 방향 단위. `imaging.measure()`가 바닥·발 중심·여백을 재고, 검사와 화면 측정선·한눈에 보기가 같은 함수를 쓴다.
- 검사 기본값은 새로 정한 규격이 아니라 현재 실행 셀이 통과하는 범위다. 장비 레이어 순서·기준점 이름은 여전히 PR #42·#44·GPT 표준 결정을 기다린다. 기준점 이름 가져오기(`foot/head/grip…`)는 그 결정 전이라 넣지 않았다.
- 시연(`docs/screenshots/studio2-*.png`): 기존 정지 시트와 PR #43의 다리 제거 몸 8방향 + E 방향 다리 연구 그림. 다리가 E에만 있으므로 검사가 "장비 묶음이 7방향에 없음"과 나머지 방향의 발 뜸을 경고한다. 이는 연구 그림의 실제 상태다.

## 6-2. 3차 구현 기록 (2026-11-12, 기준 main `59cd457`)

- 모델: `Layer.frame`, `Asset.frames`·`fps`(편집기 재생 전용)·`frame_anchors`(프레임 번호 문자열 → 발 기준점, 없으면 `anchor`)·`sheet_layout`·`sheet_columns`. 모두 기본값이 있어 1·2차 프로젝트 파일을 그대로 연다(형식 문자열 유지). 프레임 추가·복제·삭제·순서 바꾸기는 `Asset.insert_frame/delete_frame/move_frame`이 모든 방향의 레이어와 프레임별 기준점을 함께 옮긴다.
- 시트 배치(`imaging.SHEET_LAYOUTS`)는 게임이 이미 읽는 네 가지뿐이다: `cells`, `per_view`(gfx_hero 걷기 4×2·공격/무공 3×2), `views_in_cells`(정지 4×2), `rows_by_view`(gfx_enemy, 행 = 방향). 새 배치·새 셀 크기는 만들지 않았다.
- 기본 공격 프레임별 발 기준점은 `src/draw.c`의 `roots`를 192/512로 환산한 1차 프리셋 값(`hero-attack-0..5`)을 그대로 쓴다. 게임의 `fit` 배율·공격 속도·판정은 건드리지 않는다.
- 프레임 간 이동 검사는 그림 전체의 알파 가중 중심으로 잰다. 허용 30px는 현재 걷기 8장·공격·무공 4장의 연속 프레임 최대 이동보다 크게 잡은 값이다(`test_runtime_motion_sheets_pass_the_jump_tolerance`).
- 현재 실행 시트를 그대로 검사하면 나오는 경고(규격을 바꾸지 않고 그대로 보고): `warrior-attack-v1` 6프레임 모두 셀 가장자리 여백 0~1px(기준 4px), 5번째 프레임 바닥이 draw.c 기준점보다 4px 위; `warrior-retreat-v1` 4번째 프레임 발 중심 +29.4px(허용 26). 2차 허용값은 정지·걷기 셀로 정했기 때문이며, 공격·무공용 허용값을 따로 둘지는 GPT 규격·사용자 결정 사항이다. `cleave`·`sweep`·`thrust`는 정상.

## 6-3. 4차 구현 기록 (2026-11-12, 기준 main `65fbc9e`)

- `templates.py`: `Template`(구조만, 그림 없음), 기본 템플릿은 `game_specs` 프리셋과 `art/monsters/runtime.json`·실행 시트 PNG 헤더 크기에서 만든다(몬스터 프레임 수 = 시트 열 수). 형식 문자열 `paldo-asset-template/1`. NPC는 고정 셀 규격이 없어 기본 템플릿을 만들지 않았다(결정 사항).
- `autofix.py`: 배경 제거(모서리 단색 + 가장자리 연결 영역 + 선택적 1px 경계), 잡점 제거, 발 맞추기, 키 맞추기. 이미지 보정은 `Source.derived`가 붙은 새 사본만 만들고, 배치 보정은 위치·배율만 바꾼다. 측정은 검사와 같은 `imaging.measure`.
- 키 맞추기는 리샘플링 때문에 측정 높이가 배율에 대해 계단 모양이라, 비례 추정 주변 배율을 몇 개 시험해 가장 가까운 것을 고른다. 결과는 목표와 ±1px.
- AI 연계는 검토 문서([AI_INTEGRATION_REVIEW.md](AI_INTEGRATION_REVIEW.md))로 정리했다. 네트워크 호출은 넣지 않았다(데이터 반출 금지 규칙).

## 7. 미해결·한계

- Windows 실행은 이 환경에서 확인하지 못했다(코드는 경로를 `pathlib`로 다루고 OS 전용 호출이 없다).
- 레이어 회전·좌우 반전·마스크(가림 처리)는 1차에 없다. 비대칭 장비의 방향별 처리는 방향별 원화를 따로 가져오는 방식으로만 가능하다.
- 큰 원화(수천 px)를 여러 장 겹치면 Python 합성이 느려질 수 있다(1차는 192~768px 셀 기준으로 확인).
- `warrior-attack-v1.png`는 완전히 투명한 픽셀에도 RGB 값이 남아 있다. 스튜디오 합성은 투명 픽셀을 0,0,0,0으로 쓰므로 보이는 픽셀은 같지만 파일 바이트는 원본과 다르다. 보간 축소로 그리는 텍스처라면 가장자리 색이 조금 달라질 수 있으나, 게임 화면에서 차이가 나는지는 확인하지 않았다.
- 프레임 시간은 프레임마다 다르게 둘 수 없다(FPS 하나). 게임의 프레임 시간은 코드에 있고 편집기는 바꾸지 않는다.
- 배경 제거는 단색 배경용이다. 그라데이션·바닥 그림자·반투명 효과는 외부 프로그램에서 정리해야 한다. 파츠 분리(원화를 몸·옷·무기로 자르기)는 넣지 않았다.
- 키 맞추기는 ±1px 오차가 남을 수 있다.
- 그리기(붓) 기능은 없다. 그림 수정은 외부 프로그램(Krita 등)에서 하고 다시 가져온다.
